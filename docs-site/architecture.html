ratline / architecture

    Architecture

    Two properties do the heavy lifting. The control plane can only ask an agent for a catalogued operation, and there is no operation that carries a command. The agent is unprivileged, and the root helper re-validates every argument independently rather than trusting it — so C1 holds against a compromised agent, not only against a compromised control plane.

    Two listeners, two exposure policies

    The agent endpoint and the dashboard are separate listeners. Agents must reach the control plane, but C5 says the dashboard assumes it is not internet-exposed, so the two cannot share one policy:

    Dashboard

    Binds to loopback by default. Reached over VPN, Tailscale or an address allowlist. Public reachability is classified locally and warned about loudly, and the warning cannot be dismissed.

    Agent endpoint

    May face the internet. Requires a valid client certificate at the TLS handshake and rejects everything else before any application code runs.

    This distinction is easy for an operator to get wrong, so the plan requires it to be the default shape of the shipped configuration rather than a documentation footnote.

    Trust boundaries

    Each boundary is a place where one side must not trust the other, and each has a test that proves the distrust is real. B1 to B4 sit on the request path:

    Trust boundaries B1 to B8, from docs/PLAN.md §3
    # Boundary What crosses What the trusting side must not assume Proof
    B1 Browser or CLI → control plane Session cookie or API token; form and API input That the actor may see any resource they name. Authorization is resolved at the data layer, not here. RL-M1-025 matrix
    RL-M1-026 indistinguishability
    B2 Control plane → Postgres SQL, with a tenant set per transaction That application predicates are present or correct. Row-level security holds independently. RL-M1-006 — predicate removed, still zero rows
    B3 Control plane → agent Signed instruction envelopes over mTLS That the channel implies authority. Signature, target, expiry and nonce are checked before any argument is read. RL-M2-003, RL-M2-007
    B4 Agent → privd Operation requests over a unix socket That the agent is honest. privd re-validates every argument from scratch and identifies its caller by peer credentials. RL-M2-008 — a compromised agent cannot get arbitrary root
    B5 Site user → site user Nothing intended That filesystem modes alone suffice. Per-site users plus systemd sandboxing plus directory modes. RL-M3-006, RL-M6-005
    B6 Operator → host sshd Short-lived certificate with principals That a certificate implies current authorisation. Principals derive from live grants; a revocation list and session termination back it up. RL-M6-003
    B7 Git provider → control plane Webhook deliveries That a delivery is genuine. The signature is verified in constant time before parsing; replays are rejected. RL-M3-002
    B8 Control plane or agent → object storage Backup archives That the endpoint is trusted with plaintext. Archives are encrypted before leaving the host. RL-M4-013

    Which proofs exist today

    B1 and B2 are proven: RL-M1-006, RL-M1-025 and RL-M1-026 are all done. B3 is partly proven — RL-M2-003 (the signed envelope) is done, RL-M2-007 (the durable nonce store) is todo. B4 to B8 name tasks that have not started. Read from docs/tasks.yaml on 2026-08-04.

    Data model

    Tenant-scoped tables carry org_id and are covered by forced row-level security. scope_path on hierarchy nodes is materialised so an inheriting permission check resolves in one indexed query.

    Hierarchy

    ORGANIZATION → TEAM → PROJECT → ENVIRONMENT → SITE

    Permissions inherit downward. A grant on a project applies to all its environments unless a narrower deny exists, and denies always win.

    Identity

    USER · MEMBERSHIP · TEAM_MEMBER · SERVICE_IDENTITY · API_TOKEN · SSH_KEY · SSH_CERTIFICATE

    Authorization

    ROLE · ROLE_PERMISSION · GRANT · AUDIT_ENTRY

    Hosts and sites

    HOST · HOST_INVENTORY · FIREWALL_RULE · SITE · RELEASE · DEPLOYMENT · DOMAIN · CERTIFICATE · SCHEDULED_JOB

    Operations

    LOG_CHUNK · BACKUP · UPTIME_CHECK · TERMINAL_SESSION · JOB

    Secrets

    SECRET · SECRET_VERSION

    The name is plaintext so secret.read_name works without unwrapping.

    Notes on specific entities

    GRANT
    Carries subject_type (user, service identity, API token), subject_id, role_id, scope_type, scope_id, expires_at, granted_by and reason. Denies share the shape with effect: deny and always win. expires_at is evaluated at decision time and in the SQL predicate, so an expired grant is dead the instant it expires. A cleanup job exists only for hygiene — it is not in the enforcement path.
    SECRET_VERSION
    The value is sealed under a per-secret data key, itself wrapped by the key-encryption key. The version row records actor and timestamp and never the value, including in audit metadata.
    AUDIT_ENTRY
    Append-only, enforced at the database level rather than by convention: update and delete are refused outright by a trigger. Each entry chains to its predecessor by hash. Records actor, action, resource, decision, address, timestamp and request identifier. Denied decisions are recorded as prominently as allowed ones.
    RELEASE
    Directory names are system-generated timestamps, never derived from user input (RL-M3-008).
    HOST
    Stores the agent's public key and certificate serial, so revocation is a row update.
    JOB
    A queue row, tenant-scoped like everything else, so a worker cannot claim a job it could not read.

    Repository layout

    The layout encodes the constraints. src/db/internal is import-restricted by lint; src/authz/ is the only place permission logic exists; the operation catalogue is the single source both sides generate from, so the control plane and the agent cannot drift.

    Two places the tree has drifted from the plan

    docs/PLAN.md §7 puts the operation catalogue in src/ops/ and its generated Go copy in agent/internal/ops/. On disk, src/ops/ holds only a README, the catalogue lives at src/agent/catalogue.ts, and the generated file is agent/internal/protocol/catalogue_gen.go. The behaviour is what the plan describes; the paths are not.

    The plan and three README files also describe the data-access layer as “Drizzle behind a mandatory scoping layer”. src/db/internal/handle.ts uses pg directly with raw SQL, and drizzle-orm is not a dependency in package.json. The three C3 layers hold either way, but the documents name a library the code does not use.

    Stack, and where it was argued

    Stack choices from ADR 0001, checked against package.json
    LayerChoiceWhere it was argued
    Control plane languageTypeScript, strict, no any in application codeADR 0001
    RuntimeNode 22 LTS. Type stripping, so most of the tree needs no build stepADR 0001; .node-version, engines.node >= 22.6
    API frameworkHono, not NestJS — guard-and-interceptor culture pushes authorization into the route layer, the §9 anti-pattern C3 exists to preventADR 0001, docs/gates/M0.md
    DatabasePostgres 17 in development; 16 is the floor, because C3 needs forced row-level securityADR 0001, README.md
    QueuePostgres, not Redis — one fewer stateful service for a self-hosting operator, and a deploy job can be enqueued in the same transaction as the deployment rowADR 0007
    Front endReact. ADR 0001 recommended SvelteKit; the owner ruled React on 2026-08-02, closing R-03ADR 0001, docs/RISKS.md R-03
    Agent and privileged helperGo, static binaries, no module dependencies — a test asserts the module stays dependency-freeADR 0001, ADR 0004, .github/workflows/ci.yml
    AssetsAll self-hosted: fonts, icons, scripts. No external origin at runtimeADR 0001, DESIGN.md §3

    The React ruling had a consequence ADR 0001 did not anticipate: JSX is not erasable, so node --experimental-strip-types refuses a .tsx file and Vite became the project's first build step. It is paid for by keeping everything decidable in .ts — the rail, breadcrumb, chip, tension states, palette and audit view model are all data, and the components only arrange them.
